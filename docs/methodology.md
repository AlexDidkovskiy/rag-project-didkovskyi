## Лабораторна № 1

С. 12–15. Форма здачі: ініціалізований Git-репозиторій, проєктний PDF, тег `lab-1`.

| Завдання | Артефакт поточного проєкту |
| --- | --- |
| 1. Сценарій приблизно на одну сторінку, користувач, запит, критерії відповіді | `reports/lab-1/report.md`, розділ 2 |
| 2. Назва, джерело, ліцензія, оцінка обсягу корпусу | Розділ 3, `config/project.toml` |
| 3. Чотири рішення, кожне з обґрунтуванням у 1–3 реченнях | Розділ 4, README |
| 4. Ingestion, векторний індекс, ретривер, генерація, UI | Розділ 5, `reports/lab-1/architecture.md` |
| 5. `src/`, `config/`, `reports/`, README та тег на GitHub | Дерево репозиторію, `reports/lab-1/submission.md` |

Завантаження даних і повна RAG-система не є формою здачі ЛР1.
Скриншоти результатів виконання пошуку на цьому етапі не вигадуються;
результатами є проєктні матеріали, схема і конфігурація.

## Наступні етапи

- **ЛР2, с. 16–18:** фактичне завантаження 500–10 000 документів; UTF-8,
  видалення HTML, фільтрація <100 символів; ручний огляд десяти випадкових
  документів; 200–500 токенів на чанк, перекриття 10–20%; doc_id, порядковий
  номер і стабільний chunk_id; JSONL; `reports/lab-2/data-card.md` на 1–2 сторінки
  з розмірами до/після, кількістю/середнім розміром чанків, топ-20 слів, обмеженнями.
- **ЛР3, с. 19–21:** `tests/eval-set.jsonl` із 15–25 парами запит–релевантний
  чанк; готова модель без навчання; індекс із метаданими; CLI top-5 і 3–5
  прикладів; Recall@5/10 і підбір параметрів; кількість векторів, вимірність,
  розмір на диску; `reports/lab-3/report.md`, PDF та `lab-3`.
- **ЛР4, с. 22–25:** dense та BM25 на одному корпусі; порівняння на 3–5
  запитах; RRF із k=60; локальна модель до 7B; промпт із 3–5 чанками,
  цитатами та відмовами; парсинг/валідація chunk_id; одна повторна спроба
  або повідомлення про невпевненість; єдиний CLI, текст/JSON; 5–7 прикладів
  у звіті; `reports/lab-4/report.md`, PDF та `lab-4`.
- **ЛР5, с. 26–29:** `tests/gold-set.jsonl`, 30–40 пар, серед них 5–7 складних,
  3–5 негативних; Recall@5, валідність цитат, коректність відмов; 4–6
  поведінкових тестів принаймні двох типів; 2–3 метаморфні тести; 3–5
  ручних прямих ін'єкцій промпта й пропозиція захисту; чесний висновок щодо
  сценарію ЛР1, три режими відмов та способи виправлення; фінальний PDF і `lab-5`.

На с. 20 Recall@k визначено як частку запитів із релевантним результатом у
top-k. За одним еталонним чанком на запит ця частка відповідає Recall@k.
Якщо еталонів буде кілька, окремо визначити повноту за множиною релевантних
чанків і не змішувати її з часткою успішних запитів.
